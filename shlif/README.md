# שליף 🟩

כותבים מה מחפשים — ושליף שולף את התשובה מתוך מאות קבצי אקסל.

במקום לפתוח את הקובץ של מוצרי ההיגיינה, לחפש את נייר הטואלט, ואז את המותג בין אלפי שורות — כותבים:

> נייר טואלט, רך וטוב, כמה מלאי

ומקבלים את המספר, יחד עם הקובץ, הגיליון והתא שממנו הוא הגיע.

## איך משתמשים
1. **מחברים את הקבצים** — גוררים תיקייה שלמה לדף, או לוחצים "בחירת תיקייה" / "בחירת קבצים". תתי־תיקיות נסרקות גם הן.
2. **כותבים שאלה** — מה מחפשים, ואיזה פרט רוצים לדעת. פסיקים עוזרים אבל לא חובה.
3. **מקבלים תשובה** — אם נמצאה שורה אחת, מוצג הערך עצמו וכתובת התא (למשל `G7`). אם נמצאו כמה שורות, מוצג סיכום (סה״כ מלאי, טווח מחירים) עם פירוט לפי קובץ, ומתחתיו השורות עצמן. לחיצה על שורה פותחת את כל העמודות שלה.

בכניסה הראשונה נטענים נתוני דוגמה של רשת סופרים דמיונית, כדי שאפשר יהיה לנסות מיד.

### דוגמאות לשאלות
| כותבים | מקבלים |
|---|---|
| `נייר טואלט, רך וטוב, כמה מלאי` | סה״כ המלאי בכל הסניפים, ופירוט לפי קובץ |
| `נייר טואלט רך וטוב 32 גלילים, חיפה, מלאי` | המספר מהשורה האחת שמתאימה, וכתובת התא |
| `טלפון של דני כהן` | השורות של דני כהן עם הטלפון ליד כל אחת |
| `שמפו לילדים, מחיר` | טווח המחירים |
| `הזמנה 50002 סטטוס` | הסטטוס של ההזמנה |
| `7290000000014` | השורות עם הברקוד הזה |

## מה שליף מבין
- **עברית**: ה״א הידיעה ואותיות שימוש (`המלאי`, `בחיפה`), רבים ויחיד (`מגבונים` / `מגבון`), סמיכות (`חברת` / `חברה`), אותיות סופיות, גרשיים (`מק"ט`).
- **מילים נרדפות לכותרות**: `מלאי` מוצא גם עמודת `כמות` או `יתרה`; `מחיר` גם `עלות`; `טלפון` גם `נייד`; `מותג` גם `יצרן` או `ספק`. כך זה עובד גם כשכל קובץ נבנה קצת אחרת.
- **שם הקובץ והתיקייה**: אם `חיפה` או `היגיינה` מופיעים רק בשם הקובץ או התיקייה, השורות שבו עדיין נמצאות.
- **שגיאות הקלדה ומילים חלקיות**: `טואלת` או `טוא` ימצאו `טואלט` (עם הערה שהתוצאה לא מדויקת).
- **שורות כותרת מעל הטבלה**: שם הדוח, תאריך הפקה ושורות ריקות בראש הגיליון מדולגים אוטומטית.

## קבצים נתמכים
`xlsx`, `xlsm`, `xls` (גם הפורמט הישן של אקסל 97–2003), `csv`, `tsv`, וגם קובצי `xls` שהם בעצם טבלת HTML או XML (ייצוא נפוץ ממערכות ואתרים). CSV בעברית נקרא גם ב־UTF-8 וגם ב־Windows-1255.

לא נתמכים: קבצים מוגנים בסיסמה, `xlsb`, `ods`, וגם PDF. קובץ שלא נקרא מסומן ברשימת הקבצים עם הסיבה (כולל הפרט הטכני, כדי שאפשר יהיה לאבחן), ושאר הקבצים ממשיכים כרגיל.

## פרטיות
**הכול קורה בדפדפן. הקבצים לא נשלחים לשום שרת.** כדי שלא יהיה צורך לטעון אותם מחדש בכל כניסה, הנתונים נשמרים באחסון המקומי של הדפדפן (IndexedDB) במחשב הזה בלבד. "מחיקת כל הנתונים" בחלון הקבצים מוחקת אותם משם.

## עדכון הקבצים
- בכרום ובאדג׳, אחרי "בחירת תיקייה" מופיע בחלון הקבצים הכפתור **"רענון מהתיקייה"**: הוא קורא רק קבצים שהשתנו או נוספו, ומסיר קבצים שנמחקו.
- בדפדפנים אחרים בוחרים שוב את התיקייה; קבצים שלא השתנו מדולגים.

## כמה זה מחזיק
נבדק על **300 קבצי אקסל עם 1.6 מיליון שורות** (כ־250MB של קבצים), במחשב עם 4 ליבות:

| | |
|---|---|
| טעינה ראשונה ואינדוקס | כ־17 שניות |
| פתיחה חוזרת של הדף (מהאחסון המקומי) | כ־8 שניות |
| שאלה רגילה | 20–130 אלפיות שנייה |
| שאלה עם שגיאת הקלדה | עד כ־0.4 שנייה |
| זיכרון | כ־1–1.7GB בכמות הזאת (בערך 1GB לכל מיליון וחצי שורות) |

אפשר לחפש כבר בזמן שהקבצים נטענים.

## טכני
קבצים סטטיים, בלי build, בלי שרת ובלי ספריות חיצוניות:

| קובץ | תפקיד |
|---|---|
| `index.html` | הדף והעיצוב |
| `app.js` | ניהול קבצים, פיזור השאלה למנועים והצגת התשובה |
| `engine-worker.js` | מנוע חיפוש שרץ ב־Web Worker: קורא קבצים, בונה אינדקס ועונה |
| `xlsx-reader.js` | קורא `xlsx` / `xls` / `csv` / HTML / XML |
| `shared.js` | נרמול עברית, הטיות, מילים נרדפות ופענוח השאלה |
| `demo-data.js` | נתוני הדוגמה |

הקבצים מתחלקים בין כמה Workers (לפי מספר הליבות). כל אחד מחזיק אינדקס הפוך (מילה ← שורות) על החלק שלו; שאלה נשלחת לכולם במקביל והתשובות מאוחדות. לכן הטעינה מנצלת את כל הליבות והדף לא נתקע גם בזמן אינדוקס.

צריך להגיש את התיקייה דרך שרת (GitHub Pages, או `python3 -m http.server` מקומית) — פתיחה ישירה של `index.html` מהדיסק לא מאפשרת ל־Workers לעלות.
