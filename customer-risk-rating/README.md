# דירוג סיכון לקוח 🛡️ · Customer Risk Rating

מערכת שיושבת בתוך המערכת של חברת האשראי, שואבת אוטומטית את **כל** נתוני הלקוח
מכל טבלאות הנתונים (האקסלים), ומחזירה **ציון סיכון (1–10) והחלטה** תוך שנייה —
במקום שאדם יעבור טבלה־טבלה ידנית.

> **דוגמה:** יוסי מבקש הלוואה של 100,000 ₪. המערכת מזהה את יוסי, מאחדת את הנתונים
> עליו מטבלת הדמוגרפיה, טבלת התעסוקה, טבלת היסטוריית האשראי וטבלת ההתנהלות הבנקאית,
> מחשבת ציון משוקלל, ומחזירה: **1.6 / 10 → אישור ✅**, עם פירוט מלא של כל קריטריון.

---

## למה זה עובד ככה — עקרון מנחה

בהחלטות אשראי **שקיפות וניתנות־ביקורת (explainability) הן קריטיות** (רגולציה, ערעורים,
בקרה). לכן הלב של המערכת הוא **מנוע משוקלל דטרמיניסטי**: כל קריטריון מקבל תת־ציון,
כל תת־ציון מוכפל במשקל, והתוצאה ניתנת להסבר עד לרמת המספר הבודד. מעל זה יש **שכבת AI
אופציונלית** (Claude) שכותבת חוות דעת חיתום מילולית — אבל היא **מסבירה, לא מחליטה**:
הציון וההחלטה תמיד נקבעים על ידי המנוע הדטרמיניסטי.

## איך זה עובד — ארכיטקטורה

```
                ┌─────────────────────────────────────────────┐
   "יוסי,       │  RiskRatingService  (service.py)            │
   100,000 ₪" ──▶│                                             │
                │  1. DataStore      ← שואב וממזג את כל הטבלאות │
                │     (data.py)         לפי מזהה לקוח           │
                │  2. RiskEngine     ← מחשב תת־ציון לכל קריטריון│
                │     (engine.py)       × משקל  →  ציון 1–10    │
                │  3. Decision       ← 1–3 אישור / 4–6 בדיקה   │
                │                       / 7–10 דחייה           │
                │  4. Explain        ← הסבר מילולי (+AI אופצ')  │
                └─────────────────────────────────────────────┘
                                    │
                                    ▼
        {  score: 1.6,  decision: "approve",  breakdown: [...]  }
```

* **טבלאות הנתונים** (`data/sample/*.csv`) — כמו האקסלים של החברה. כל טבלה מכילה חתך
  אחר (דמוגרפיה, תעסוקה, אשראי, בנק), וכולן מקושרות דרך `customer_id`.
* **מודל הניקוד** (`config/scoring_model.yaml`) — כאן קובעים אילו קריטריונים נכללים,
  **כמה אחוז כל אחד משפיע**, ואיך כל ערך הופך לתת־ציון סיכון. זהו קובץ שאנליסט עורך
  ללא נגיעה בקוד.

## התחלה מהירה

### 1. התקנה
```bash
cd customer-risk-rating
pip install -r requirements.txt          # ליבה + web + ai + בדיקות
# או המינימום בלבד:  pip install pandas PyYAML openpyxl
```

### 2. שורת פקודה (CLI)
```bash
export PYTHONPATH=src          # או:  pip install -e .

# יוסי מבקש 100,000 ₪:
python -m risk_rating.cli --customer "יוסי" --amount 100000

# לפי מזהה, עם הסבר מילולי:
python -m risk_rating.cli -c C1003 -a 100000 --explain

# רשימת כל הלקוחות במערכת:
python -m risk_rating.cli --list

# פלט JSON (לשילוב במערכות אחרות):
python -m risk_rating.cli -c "מרים" -a 250000 --json
```

### 3. ממשק Web
```bash
pip install fastapi uvicorn
PYTHONPATH=src uvicorn risk_rating.api:app --reload
# פותחים http://127.0.0.1:8000  — בוחרים לקוח, מזינים סכום, מקבלים ציון.
```

### 4. הדגמה מיידית ללא התקנה
פותחים את הקובץ [`web/demo.html`](web/demo.html) ישירות בדפדפן — כל החישוב מתבצע
בדפדפן, ללא שרת וללא התקנה.

### 5. מתוך קוד Python
```python
from risk_rating import RiskRatingService

service = RiskRatingService()                 # טוען את המודל ואת הנתונים
result = service.assess("יוסי", 100_000)      # שואב נתונים + מחשב ציון

print(result.score)            # 1.57
print(result.decision_id)      # "approve"
print(result.to_dict())        # פלט מלא כולל פירוט לכל קריטריון
```

## מודל הניקוד — הקריטריונים והמשקלים

ברירת המחדל (`config/scoring_model.yaml`). הציון הוא **ציון סיכון**: נמוך = טוב.

| קריטריון | משקל | הערה |
|---|---:|---|
| יכולת החזר (DTI) כולל ההלוואה המבוקשת | 20% | היחס בין ההחזר החודשי הכולל להכנסה |
| מצב תעסוקתי | 15% | שכיר קבוע / עצמאי / מובטל … |
| היסטוריית תשלומים (פיגורים) | 15% | פיגורים ב-12 החודשים האחרונים |
| רמת הכנסה חודשית | 12% | |
| כשלי אשראי / הוצאה לפועל | 10% | |
| ניצול מסגרות אשראי | 8% | |
| ותק במקום העבודה | 7% | |
| גיל | 5% | |
| התנהלות בנקאית (חריגות ממסגרת) | 5% | |
| יציבות משפחתית (מצב משפחתי) | 3% | |
| **סה"כ** | **100%** | |

**ספי ההחלטה:** `1–3 → אישור` · `4–6 → בדיקה ידנית / אישור חלקי` · `7–10 → דחייה`.

### התאמה אישית
כל אלה נערכים ב-`config/scoring_model.yaml` בלבד — ללא שינוי קוד:
* לשנות **משקל** של קריטריון (רק לוודא שהסכום נשאר 1.0).
* לשנות את **הרצועות** שקובעות איך ערך גולמי הופך לתת־ציון.
* לשנות את **ספי ההחלטה** (למשל להחמיר: אישור רק עד 2).
* להוסיף/להסיר קריטריונים. קריטריון מסוג `numeric_bands` צריך רצועות; מסוג
  `categorical` צריך מיפוי ערכים. קריטריון מחושב (למשל DTI) משתמש ב-`source: "derived:<שם>"`
  ומוגדר ב-`src/risk_rating/features.py`.

## שכבת ה-AI (אופציונלי)

ברירת המחדל: הסבר **תבניתי** דטרמיניסטי, שעובד תמיד וללא תלות חיצונית.

אם מוגדר `ANTHROPIC_API_KEY` ומותקנת חבילת `anthropic`, אפשר לבקש **חוות דעת חיתום**
שכותב Claude — מנוסחת בעברית, מבוססת אך ורק על הנתונים שהמנוע חישב:
```bash
export ANTHROPIC_API_KEY=sk-ant-...
python -m risk_rating.cli -c "דוד" -a 100000 --ai
```
ברירת המחדל היא הדגם `claude-opus-5`; להוזלה אפשר `export RISK_EXPLAIN_MODEL=claude-haiku-4-5`.
אם ה-AI לא זמין או מסרב — המערכת נופלת חזרה להסבר התבניתי ולעולם לא נחסמת.

## שימוש בנתונים אמיתיים

מפנים את המערכת לתיקייה עם קבצי ה-CSV/Excel האמיתיים:
```bash
python -m risk_rating.cli --data /path/to/real/tables -c "שם לקוח" -a 100000
```
דרישות: לכל טבלה עמודת `customer_id`, ושמות העמודות תואמים ל-`source` שבמודל הניקוד
(או שמעדכנים את המודל בהתאם). קבצים ללא `customer_id` מדולגים בשקט; שדות חסרים
מקבלים הערכת סיכון ברירת־מחדל (`missing_risk`) ומסומנים בפלט.
