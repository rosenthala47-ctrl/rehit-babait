# דירוג סיכון לקוח 🛡️ · Customer Risk Rating

מערכת שיושבת בתוך המערכת של חברת האשראי, שואבת אוטומטית את **כל** נתוני הלקוח
מכל טבלאות הנתונים (האקסלים), ומחזירה **ציון סיכון (1–10) והחלטה** תוך שנייה —
במקום שאדם יעבור טבלה־טבלה ידנית.

> **דוגמה:** יוסי מבקש הלוואה של 100,000 ₪. המערכת מזהה את יוסי, מאחדת את הנתונים
> עליו מטבלאות החברה (דמוגרפיה, תעסוקה, בנק), **שולפת את דירוג האשראי שלו ממרשם
> נתוני האשראי של בנק ישראל** (לפי ת"ז, בכפוף להסכמתו), מחשבת ציון משוקלל על פני
> 17 קריטריונים, ומחזירה: **2.1 / 10 → אישור ✅**, עם פירוט מלא של כל קריטריון.

---

## למה זה עובד ככה — עקרון מנחה

בהחלטות אשראי **שקיפות וניתנות־ביקורת (explainability) הן קריטיות** (רגולציה, ערעורים,
בקרה). לכן הלב של המערכת הוא **מנוע משוקלל דטרמיניסטי**: כל קריטריון מקבל תת־ציון,
כל תת־ציון מוכפל במשקל, והתוצאה ניתנת להסבר עד לרמת המספר הבודד. מעל זה יש **שכבת AI
אופציונלית** (Claude) שכותבת חוות דעת חיתום מילולית — אבל היא **מסבירה, לא מחליטה**:
הציון וההחלטה תמיד נקבעים על ידי המנוע הדטרמיניסטי.

```
                ┌─────────────────────────────────────────────┐
   "יוסי,       │  RiskRatingService  (service.py)            │
   100,000 ₪" ──▶│                                             │
                │  1. DataStore      ← שואב וממזג את טבלאות     │
                │     (data.py)         החברה לפי מזהה לקוח     │        ┌──────────────┐
                │  2. CreditBureau   ← שולף דירוג אשראי לפי ת"ז │───────▶│  בנק ישראל   │
                │     (bureau.py)       (בכפוף להסכמת הלקוח)    │◀───────│ מרשם נתוני   │
                │  3. RiskEngine     ← תת־ציון לכל קריטריון     │        │   האשראי     │
                │     (engine.py)       × משקל  →  ציון 1–10    │        └──────────────┘
                │  4. Decision       ← 1–3 אישור / 4–6 בדיקה   │
                │                       / 7–10 דחייה           │
                │  5. Explain        ← הסבר מילולי (+AI אופצ')  │
                └─────────────────────────────────────────────┘
                                    │
                                    ▼
        {  score: 1.6,  decision: "approve",  breakdown: [...]  }
```

* **טבלאות החברה** (`data/sample/*.csv`) — כמו האקסלים של החברה: דמוגרפיה, תעסוקה
  והתנהלות בנקאית, מקושרות דרך `customer_id`.
* **מרשם נתוני האשראי** (`bureau.py`) — נתוני האשראי (פיגורים, כשלים, ניצול מסגרות,
  דירוג לשכה) **נשלפים חיים מבנק ישראל** לפי ת"ז, ולא יושבים בטבלה מקומית. ראו למטה.
* **מודל הניקוד** (`config/scoring_model.yaml`) — כאן קובעים אילו קריטריונים נכללים,
  **כמה אחוז כל אחד משפיע**, ואיך כל ערך הופך לתת־ציון סיכון. זהו קובץ שאנליסט עורך
  ללא נגיעה בקוד.

## התחלה מהירה

### 1. התקנה
```bash
cd customer-risk-rating
pip install -r requirements.txt          # ליבה + web + ai + בדיקות
# או המינימום בלבד:  pip install pandas PyYAML openpyxl
```

### 2. שורת פקודה (CLI)
```bash
export PYTHONPATH=src          # או:  pip install -e .

# יוסי מבקש 100,000 ₪:
python -m risk_rating.cli --customer "יוסי" --amount 100000

# לפי מזהה, עם הסבר מילולי:
python -m risk_rating.cli -c C1003 -a 100000 --explain

# עם מטרת הלוואה ובטוחה (Conditions + Collateral):
python -m risk_rating.cli -c "יוסי" -a 100000 --purpose vehicle --collateral full_secured

# רשימת כל הלקוחות במערכת:
python -m risk_rating.cli --list

# ללא הסכמת הלקוח — המערכת לא תפנה לבנק ישראל (נתוני האשראי יסומנו כחסרים):
python -m risk_rating.cli -c "יוסי" -a 100000 --no-consent

# פלט JSON (לשילוב במערכות אחרות):
python -m risk_rating.cli -c "מרים" -a 250000 --json
```

### 3. ממשק Web
```bash
pip install fastapi uvicorn
PYTHONPATH=src uvicorn risk_rating.api:app --reload
# פותחים http://127.0.0.1:8000  — בוחרים לקוח, מזינים סכום, מקבלים ציון.
```

### 4. הדגמה מיידית ללא התקנה
פותחים את הקובץ [`web/demo.html`](web/demo.html) ישירות בדפדפן — כל החישוב מתבצע
בדפדפן, ללא שרת וללא התקנה.

### 5. מתוך קוד Python
```python
from risk_rating import RiskRatingService

service = RiskRatingService()                 # טוען את המודל ואת הנתונים
result = service.assess("יוסי", 100_000)      # שואב נתונים + מחשב ציון

print(result.score)            # 1.57
print(result.decision_id)      # "approve"
print(result.to_dict())        # פלט מלא כולל פירוט לכל קריטריון
```

## מודל הניקוד — 17 קריטריונים לפי חמשת ה-C's

המודל (`config/scoring_model.yaml`) מסודר לפי **חמשת ה-C's של אשראי** (5 C's of credit) —
המסגרת המקובלת בחיתום. משקלי בלוק ה-Character נגזרים בהשראת פרופורציות FICO / VantageScore
(ראו "מתודולוגיה ומקורות" למטה). הציון הוא **ציון סיכון**: נמוך = טוב.

**Character — היסטוריית והתנהגות אשראי · 40%**
| קריטריון | משקל |
|---|---:|
| דירוג אשראי (לשכת נתוני אשראי / בנק ישראל) | 10% |
| היסטוריית תשלומים (פיגורים ב-12 ח') | 10% |
| כשלי אשראי / הוצל"פ / כונס / חשבון מוגבל | 7% |
| ניצול מסגרות אשראי | 6% |
| אורך היסטוריית האשראי | 4% |
| בקשות אשראי אחרונות (6 ח') — "רעב לאשראי" | 3% |

**Capacity — יכולת החזר · 35%**
| קריטריון | משקל |
|---|---:|
| יכולת החזר (DTI) כולל ההלוואה המבוקשת | 15% |
| רמת הכנסה חודשית | 7% |
| מינוף קיים (סך חוב ביחס להכנסה שנתית) | 6% |
| מצב תעסוקתי | 5% |
| ותק במקום העבודה | 2% |

**Capital — הון / כרית ביטחון · 8%** · **Collateral — בטוחות · 7%** · **Conditions — מטרה ופרופיל · 10%**
| קריטריון | משקל |
|---|---:|
| נזילות / חיסכון (יתרה ממוצעת בעו"ש) | 4% |
| התנהלות בנקאית (חריגות ממסגרת) | 4% |
| בטוחה / ביטחונות להלוואה | 7% |
| מטרת ההלוואה | 5% |
| יציבות משפחתית (מצב משפחתי) | 3% |
| גיל | 2% |

**סה"כ: 100%.**  ספי ההחלטה: `1–3 → אישור` · `4–6 → בדיקה ידנית` · `7–10 → דחייה`.

> **הערת הוגנות (fair lending):** משקלי הגיל והמצב המשפחתי הושארו נמוכים בכוונה (יחד 5%)
> — במודלים רבים מפחיתים או מנטרלים גורמים דמוגרפיים מטעמי הוגנות ואנטי-אפליה. במודל
> תפעולי אמיתי יש לבחון זאת מול הרגולציה.

### מתודולוגיה ומקורות
* **FICO** — משקלי הליבה: היסטוריית תשלומים 35%, ניצול/חוב 30%, אורך היסטוריה 15%,
  אשראי חדש 10%, תמהיל 10%. ([myFICO](https://www.myfico.com/credit-education/whats-in-your-credit-score))
* **VantageScore 4.0** — דגש מוגבר על היסטוריית תשלומים ואשראי חדש, ועומק אשראי (גיל
  החשבונות). ([VantageScore](https://vantagescore.com/consumers/blog/the-complete-guide-to-your-vantagescore))
* **5 C's of Credit** — Character, Capacity, Capital, Collateral, Conditions; "חוזק ב-C
  אחד יכול לקזז חולשה באחר". ([Corporate Finance Institute](https://corporatefinanceinstitute.com/resources/commercial-lending/5-cs-of-credit/))
* **מרשם נתוני האשראי, בנק ישראל** — התחייבויות, תנאי אשראי, בטוחות, אופן תשלום, ונתוני
  כונס רשמי / הוצל"פ / חשבונות מוגבלים. ([מערכת נתוני אשראי](https://www.creditdata.org.il/))

### התאמה אישית
כל אלה נערכים ב-`config/scoring_model.yaml` בלבד — ללא שינוי קוד: משקלים (שהסכום נשאר 1.0),
רצועות, ספי החלטה, והוספה/הסרה של קריטריונים. קריטריון מחושב (DTI, מינוף קיים) משתמש
ב-`source: "derived:<שם>"` ומוגדר ב-`src/risk_rating/features.py`.

### התאמה אישית
כל אלה נערכים ב-`config/scoring_model.yaml` בלבד — ללא שינוי קוד:
* לשנות **משקל** של קריטריון (רק לוודא שהסכום נשאר 1.0).
* לשנות את **הרצועות** שקובעות איך ערך גולמי הופך לתת־ציון.
* לשנות את **ספי ההחלטה** (למשל להחמיר: אישור רק עד 2).
* להוסיף/להסיר קריטריונים. קריטריון מסוג `numeric_bands` צריך רצועות; מסוג
  `categorical` צריך מיפוי ערכים. קריטריון מחושב (למשל DTI) משתמש ב-`source: "derived:<שם>"`
  ומוגדר ב-`src/risk_rating/features.py`.

## מרשם נתוני האשראי של בנק ישראל 🏦

ברגע שמתקבלת בקשת הלוואה, המערכת פונה למרשם נתוני האשראי לפי ת"ז הלקוח ושולפת את
דירוג האשראי שלו.

**המציאות בישראל:** אין API ציבורי פתוח. לפי **חוק נתוני אשראי (2016)**, הגישה מותנית ב:
היות (או עבודה מול) **לשכת נתוני אשראי מורשית**, **הסכמת הלקוח** למשיכת הנתונים, וחיבור
מאובטח ומאומת (מפתח API / תעודות mTLS). לכן המערכת בנויה עם **מחבר נשלף** (`bureau.py`):

| מחבר | מתי | תיאור |
|---|---|---|
| `MockBankOfIsraelClient` | ברירת מחדל | סימולציה — קורא את `data/bureau/credit_register.csv`, כך שכל הזרימה עובדת offline. |
| `HttpBankOfIsraelClient` | אינטגרציה אמיתית | שלד HTTP מוכן — ממלאים URL, תעודות ומיפוי תשובה כשמקבלים גישה. |

בוחרים מחבר דרך משתנה הסביבה `RISK_BUREAU` (`mock` — ברירת מחדל, או `http`).

**שער הסכמה:** ללא הסכמת לקוח המערכת **לא** פונה למרשם (כמו בחוק). בלי נתוני אשראי,
הקריטריונים הרלוונטיים מקבלים הערכת סיכון ברירת־מחדל ומסומנים בפלט (נסו `--no-consent`).

### חיבור למרשם אמיתי
```bash
export RISK_BUREAU=http
export RISK_BUREAU_URL=https://<endpoint-של-לשכת-אשראי-מורשית>
export RISK_BUREAU_API_KEY=...
export RISK_BUREAU_CLIENT_CERT=/path/client.pem     # mTLS
export RISK_BUREAU_CLIENT_KEY=/path/client.key
export RISK_BUREAU_CA_BUNDLE=/path/ca.pem
```
נותר רק למפות את שמות השדות שבתשובת המרשם האמיתית, בפונקציה `HttpBankOfIsraelClient._parse`.
בפועל חברת אשראי ניגשת למרשם של בנק ישראל דרך לשכת נתוני אשראי מורשית — ה-URL יצביע על
ה-endpoint של הלשכה.

## שכבת ה-AI (אופציונלי)

ברירת המחדל: הסבר **תבניתי** דטרמיניסטי, שעובד תמיד וללא תלות חיצונית.

אם מוגדר `ANTHROPIC_API_KEY` ומותקנת חבילת `anthropic`, אפשר לבקש **חוות דעת חיתום**
שכותב Claude — מנוסחת בעברית, מבוססת אך ורק על הנתונים שהמנוע חישב:
```bash
export ANTHROPIC_API_KEY=sk-ant-...
python -m risk_rating.cli -c "דוד" -a 100000 --ai
```
ברירת המחדל היא הדגם `claude-opus-5`; להוזלה אפשר `export RISK_EXPLAIN_MODEL=claude-haiku-4-5`.
אם ה-AI לא זמין או מסרב — המערכת נופלת חזרה להסבר התבניתי ולעולם לא נחסמת.

ישראל" והגדרת `RISK_BUREAU=http`.

## ⚠️ הבהרה

זהו פרויקט **הדגמה/חינוכי**. הנתונים ב-`data/sample/` בדיוניים לחלוטין. המשקלים
והרצועות הם ברירת מחדל סבירה לצורך הדגמה — **לא** מודל אשראי מאושר רגולטורית. לפני
שימוש אמיתי בהחלטות אשראי נדרשים כיול על נתונים היסטוריים, בדיקת הטיות והוגנות,
ואישור רגולטורי ומשפטי.
